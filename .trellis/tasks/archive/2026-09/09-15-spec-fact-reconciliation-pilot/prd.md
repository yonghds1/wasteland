# spec 事实对账（试点：backend/quality-guidelines.md）

## Goal

对 `.trellis/spec/backend/quality-guidelines.md`（371 行）做一次**事实对账**：逐条核验其中关于本仓库
客观状态的事实性陈述，把与代码不符的改对，并**为判定"仍然属实"的条目留下核验依据**。

本任务是一次**试点**：用单文件试出方法论是否可行、成本多大、判据是否够用；全量推广到其余 19 个
spec 文件的决定在试点产出之后再下（见 Out of Scope）。

### 为什么值得做

`CLAUDE.md` 要求所有 AI 助手不要凭预训练记忆猜架构，并把 `.trellis/spec/` 定为 Single Source of
Truth。因此 spec 的每条事实断言都是**后续每个会话在决策前会读、并会照做的输入**。

本会话已两次被过期信息污染决策：一次是我依据「core 层无 abort 管线」把并不存在的缺口当高成本项
推荐给用户（真实实现用的是 RxJS `abort$`，我按 `AbortController` 关键词搜空）；另一次同类的
doom-loop/retry 判断。目标文件里同性质的问题成片存在——同一份文件里，"没有配置 linter"（实际
eslint + prettier 都在且 lint 就是门禁第 2 道）与"没有真实外部模型 provider"（`openai.ts` 492 行、
`claude.ts` 451 行是真 HTTP 实现）并存。

## Requirements

- **R1 范围 = 事实性断言，不是全部文字**。判定标准：
  **该句是否在断言"本仓库当前的客观状态"？**
  - 是 → 纳入核验（例："没有配置 linter"、"`test/cli.test.js` 验证…"）
  - 否，属行为规范 → **不纳入、不改**（例："Don't suppress a failing gate with `|| true`"）
  - 边界情形（规范的**前提事实**已被推翻）→ 只改前提，不动规范本身
- **R2 逐条核验，不许抽查**。产出对账表，每行含：
  `断言原文（含行号） → 判定（属实 / 已过期 / 属规范不适用） → 核验证据（命令或文件） → 处理`
  **"仍然属实"同样必须给出证据**——否则等于没查。
- **R3 整段陈述单独核对**。`quality-guidelines.md` 的 `## Observed Baseline`（L7-18）与
  `## Current Check Commands`（L253）是整段式描述，**天生容易整段过期**。要求逐条进表，
  不允许"这节看起来还行"就跳过。
- **R4 只改事实描述**。不调整规范性条文的措辞、不统一文风、不为显得新而加时间戳/日期。
- **R5 明确不动的区域**：`docs/`、其余 19 个 spec 文件、任何记忆文件。本任务由此暴露的
  `docs/` 漂移只**记录**不修（spec 自身的规则是"spec 为准、同任务修 docs"，但那属另一轮范围）。
- **R6 试点产出必须能回答三个问题**（供推广决策）：
  1. 这个文件里事实断言共几条？其中过期的几条？
  2. 单文件对账的实际成本（读码与核验的步数/时间量级）？
  3. 判据 R1 在实操中是否够用——有没有遇到难以判定的边界情形？
